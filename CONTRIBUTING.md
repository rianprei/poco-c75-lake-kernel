# Contributing

The most valuable contribution right now is **hardware test results** on a real `lake` device (POCO C75 4G / Redmi 14C 4G), following [`docs/DEVICE-TEST-PROTOCOL.md`](docs/DEVICE-TEST-PROTOCOL.md). Flashing can bootloop or brick the device. Read [`docs/SAFETY.md`](docs/SAFETY.md) before Z0–T3. Only T-1 and T3 write flash. Z0, R3, and T2b are read-only.

Please open an issue with: device model (`ro.product.device`, example `lake`) and firmware (`ro.build.version.incremental`), which step you ran (Z0/R3/T-1/T2b/T3), `dmesg` and `adb bugreport` excerpts, and the sha256 of every image involved. Before pasting a bugreport, strip serial numbers, IMEI, and network identifiers. The issue gets excerpts. Keep raw files locally and do not attach them: `z0_fastboot_before.txt`, `t2b_readout.txt`, `t2b_post_readout.txt`, `baseline_modules.txt`, `baseline_dmesg.txt`, and a listing of `/sys/fs/pstore`.

Code changes: keep tools read-only on inputs, add a negative (sabotage) test for every new gate. Run `./tools/run_all_checks.sh` and `./tools/selftest_backprop.sh` (each §V row). CRC-gate sabotage is `tools/selftest_gates.sh`. Two vocabularies stay in use together. Device-facing claims are labelled `MEASURED` (with the command) or `UNVERIFIED`; `docs/FACTS.md` also uses `CROSS-CHECKED` and `SINGLE-SOURCE`. `SPEC.md` V14 also uses `INFERRED` and `UNKNOWN`. Host-scope claims use `host-verified`, `rebuild-reproducible`, `hardware-unverified`, and `boot-unproven`. Never commit partition dumps, boot images, or anything containing device identifiers.
