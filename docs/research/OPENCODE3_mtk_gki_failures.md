## §1. OWLXS/android_kernel_common (branch lamu-6.6.142) + OWLXS/android_kernel_motorola_lamu-mediatek_modules

**Contexto (MEASURED):** fork do GKI **android15-6.6.142_r00** para o Motorola moto g05 (lamu) — **mesma família de SoC do lake (MT6768/MT6769, Helio)**. Diferença crucial para o lake: o projeto lamu **reconstrói também os módulos** a partir do fonte Motorola `kernel_device_modules-6.6` (subtrees `connectivity/`, `gpu/`, `mtkcam/`, `met_drv_v3/` — MEASURED no inventário de commits), enquanto o lake **mantém os .ko stock binários**. Os commits ainda assim documentam exatamente as interfaces kernel↔módulo que quebram.

### 3.0 Âncoras MEDIDAS do lake (fatos locais que amarram a tabela)

|---|---|---|

| **Módulos do lake são kCFI-built** | `readelf -sW CPU_DVFS.ko` → símbolos `__kcfi_typeid_mt_cpufreq_find_Vboot_idx`, `__kcfi_typeid_seq_read`… | comando executado hoje — MEASURED |

### 3.1 Tabela

| Sintoma (como aparece) | Causa raiz | Correção | Como detectar ANTES de flashar |
|---|---|---|---|
| **Pânico kCFI no primeiro insmod** (caso C1: `bootprof.ko`; no lake o análogo seria o primeiro módulo do ramdisk r00 do vendor_boot) | kernel `CFI_CLANG=y` + módulos construídos **sem** kCFI (divergência do par) | manter o **contrato dos binários existentes**: módulos do lake **são kcfi** (âncora 3.0) → **`CONFIG_CFI_CLANG=y` obrigatório**; nunca desligar CFI "por segurança" numa v1 | `readelf -sW <módulo>.ko \| grep __kcfi_typeid` → se >0, kernel precisa de CFI=y; diff config nova vs `config.stock` deve ter `CONFIG_CFI_CLANG` idêntico |
| **`Unknown symbol X (err -2)`** no dmesg (caso C12: `rfkill_alloc` → WiFi/BT mortos; generalização: qualquer export podado) | build nova perdeu/podou export que o módulo vendor exige (`TRIM_UNUSED_KSYMS`, config delta, lista KMI editada, protected-exports filter do caso C15) | listas KMI **idênticas** às do r12 (não editar para menos); `--notrim` só em build de debug (mascara quebra); sem reimplantar ABI visível (LZ4 do caso C13) | **pré-flash host-side**: `comm -23 modules_undef_symbols.txt <(awk '$3=="vmlinux"{print $2}' vmlinux.symvers.novo)` → vazio; rodar `gate_kmi_crc.sh` → PASS; pós-boot: `insmod` manual + dmesg (como o C12 fez) |
| **`X: disagrees about version of symbol Y`** | CRC divergente sob `MODVERSIONS` — patch/config mudou struct ou assinatura | construir do **tag exato** (android15-6.6 r12, commit 5a0ffb447c) com `config.stock` sem patches que toquem ABI; patches de sched/perf (estilo OWLXS `2d68de03`) podem mover CRC — tratar como risco | `gate_kmi_crc.sh` (2309/0 hoje) + diff `Module.symvers` novo vs oficial — 0 divergências antes de empacotar |
| **`module_layout` disagreement / vermagic rejeitado** | tail do vermagic ≠ (`SMP preempt mod_unload modversions aarch64`); o token de **release é ignorado** com CRCs (C14) | gerar `CONFIG_LOCALVERSION="-4k"` e flags idênticos; deixar o hash `-g<sha>-ab<n>-` cair onde cair | comparar `modinfo -F vermagic` dos 3 grupos do lake vs o tail do build novo; o tail tem de ser byte-a-byte igual |
| **`.ko` rejeitado: "unsupported RELA"** (relocations GOT — casos C2/C3) | módulo construído com LTO/visibility que o module loader do arm64 não processa | para o lake (módulos **stock binários**): manter kernel `LTO_NONE=y` (stock); **não** aplicar o experimento ThinLTO do OWLXS na v1; se algum dia rebuildar módulos, espelhar LTO nos dois lados | `readelf -rW <módulo>.ko \| grep GOT` — nos módulos do lake dá **0** (âncora 3.0); qualquer kernel custom que gere módulos deve manter 0 |
| **Bootloop com todos os CRCs OK** (caso C13) | built-in × módulo vendor: kernel custom com `zram/zsmalloc=y` enquanto o Android requisita os **módulos stock** (vendor_boot ramdisk/system_dlkm) — o modprobe falha/ordem quebra e o boot morre; ou helper que burla ordem/CRC de módulo | manter **`ZRAM=m`, `ZSMALLOC=m`** exatamente como o stock (âncora 3.0 — no lake a armadilha não existe se o diff de config ficar vazio); nunca usar patch "helper" amplo; se built-in for inevitável, devolver **EEXIST** pela modalidade estreita | diff config novo vs stock: qualquer `=m → =y` em zram/zsmalloc/rfkill/cfg80211 = bandera vermelha; conferir modules.load do system_dlkm (79 entradas) contra built-ins do build novo |
